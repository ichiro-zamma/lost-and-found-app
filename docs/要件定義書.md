# 要件定義書

## 1. プロジェクト概要

| 項目 | 内容 |
|---|---|
| アプリ名 | 落とし物管理・マッチングアプリ |
| 位置づけ | 研修の卒業制作 |
| 技術スタック | React.js, Next.js, Prisma, PostgreSQL |
| 開発方針 | まず基本機能(MVP)を作り、時間があれば拡張機能を追加していく |

## 2. アプリ概要

利用者はログインして「落とし物」または「拾得物」を登録する。登録時には種類・色・紛失/拾得場所・日時を入力し、落とした人はさらに本人確認用の秘密情報(自由記述。例:「財布の中に犬の写真が入っている」)も記録する。システムは登録内容から自動で一致度スコアを計算し、条件が近い落とし物と拾得物をマッチング候補として提示する。

拾った人はアプリで拾得物情報を先に登録し、実物を最寄りの施設(駅の忘れ物センター、学校など)に届ける。管理者が届いた実物を確認し、その拾得物データに保管施設を紐付ける(拾得物の登録時点で施設が未設定でも、マッチング候補としてはすでに表示される。施設が紐付いた時点で候補に施設名・住所も追加表示される)。落とし主は候補を見て施設に行き、施設の管理者が秘密情報と実物を対面で照合して本人確認を行う。実物が手渡された後、施設管理者がアプリ上で返却済みへとステータスを更新する。

## 3. 対象ユーザーと役割

複数の施設(駅・学校など)をまたいで利用できるアプリとして設計する。

### 3-1. 落とした人
- ログインして落とし物を登録する(種類・色・場所・日時・本人確認用の秘密情報)。この登録一度きりで本人確認用の情報入力は完結する
- マッチング候補が提示されたら確認する(施設情報が付いていれば合わせて確認する)
- 施設に行き、管理者との対面確認を経て実物を受け取る

### 3-2. 拾った人
- ログインして拾得物を登録する(種類・色・場所・日時)。この時点ではまだ施設は未設定でよい
- 実物を最寄りの施設(駅・学校など)に届ける
- これ以降の対応(施設紐付け・本人確認・返却)には関与しない

### 3-3. 施設の管理者
- 実物が届いたら、その拾得物データに自施設を紐付ける(保管開始。マッチング候補には施設紐付け前から表示されているが、この時点で候補に施設情報が追加表示される)
- 落とし主が来訪した際、登録された秘密情報と実物を対面で照合し本人確認する
- 実物を落とし主に手渡した後、アプリ上で「返却済み」にステータスを更新する
- (自施設で保管している拾得物のみを管理対象とする)

## 4. 機能要件

### 4-1. MVP(必須機能)

| 機能 | 内容 |
|---|---|
| 会員登録・ログイン/ログアウト | メールアドレス・パスワードでのアカウント登録、ログイン状態の管理 |
| 落とし物登録機能 | 種類・色・紛失場所・紛失日時・本人確認用の秘密情報を登録できる |
| 拾得物登録機能 | 種類・色・拾得場所・拾得日時を登録できる |
| マッチング機能 | 種類・色・場所・日時の一致度をスコア化(0〜100点)し、候補を一覧表示する。拾得物は施設紐付け前でも候補として表示される |
| 本人確認機能 | 施設管理者が、登録された秘密情報と実物を対面で照合し、一致すれば本人確認済み(is_verified)とする |
| 施設管理機能 | 管理者が拾得物に自施設を紐付ける(紐付け後、候補に施設名・住所が追加表示される)、返却済みへのステータス更新を行う |
| ステータス管理機能 | 落とし物・拾得物ごとに「未マッチング／確認中／返却済み」の状態を管理する。返却済みへの更新は施設管理者のみ実行できる |

### 4-2. 拡張機能(時間があれば追加)

| 機能 | 内容 |
|---|---|
| 管理者ダッシュボード | 自施設の未対応件数・マッチング中件数・返却済み件数などを集計・可視化する |
| メッセージ機能 | 落とした人と拾った人(または管理者)がアプリ上でやり取りできる |
| 通知機能 | マッチング候補が見つかった際にメール/画面通知を行う |
| 検索・絞り込み機能 | カテゴリ・場所・期間で一覧を絞り込む |
| 返却履歴機能 | いつ・どの管理者が返却対応をしたかを記録として残す |

## 5. 非機能要件

| 項目 | 内容 |
|---|---|
| セキュリティ | パスワードはハッシュ化して保存する。本人確認は施設管理者による対面照合とし、なりすましによる不正受け取りを防ぐ。返却済みへの更新は管理者のみが行える |
| データアクセス制御 | 施設管理者は自施設に紐づく拾得物のみ閲覧・操作できる |
| 対応デバイス | 一般ユーザー・管理者ともにスマートフォンからの利用を想定する |

## 6. 画面一覧(MVP)

1. ログイン / 会員登録画面
2. 落とし物登録画面
3. 拾得物登録画面
4. マッチング候補一覧画面(自分の落とし物に対する候補を表示。施設情報は紐付け後に表示)
5. 管理者向け:拾得物一覧・施設紐付け画面
6. 管理者向け:本人確認・返却処理画面(秘密情報の確認、返却済みへのステータス更新)

## 7. 業務フロー(概要)

```
[落とした人]                 [拾った人]                [施設管理者]
落とし物登録                 拾得物登録
(秘密情報を含む)              　↓
       ←──── システムが自動でマッチング候補を算出(施設未定でも表示) ────
                              実物を施設に届ける
                                                        施設を紐付け(候補に施設情報が追加表示)
候補を確認し施設へ向かう
       ↓
                                                        秘密情報と実物を対面で照合(本人確認)
       ↓                                                       ↓
実物を受け取る          ←─────────────────────────  実物を手渡す
                                                        アプリ上で「返却済み」に更新
```
