# 要件定義書

## 1. プロジェクト概要

| 項目 | 内容 |
|---|---|
| アプリ名 | 落とし物管理・マッチングアプリ |
| 位置づけ | 研修の卒業制作 |
| 技術スタック | Next.js (App Router) / React / TypeScript / Prisma / PostgreSQL / Tailwind CSS |
| 開発環境 | Docker / Dev Containers / pnpm |
| 開発方針 | まず基本機能(MVP)を作り、時間があれば拡張機能を追加していく |

## 2. アプリ概要

利用者はログインして「落とし物」または「拾得物」を登録する。登録時には種類・色・紛失/拾得場所・日時・写真（任意）を登録し、落とした人はさらに本人確認用の秘密情報(自由記述。例:「財布の中に犬の写真が入っている」)も記録する。システムは登録内容から自動で一致度スコアを計算し、条件が近い落とし物と拾得物をマッチング候補として提示する。

拾った人はアプリで拾得物情報を先に登録し、実物を最寄りの施設(駅の忘れ物センター、警察署など)に届ける。管理者が届いた実物を確認し、その拾得物データに保管施設を紐付ける(拾得物の登録時点で施設が未設定でも、マッチング候補としてはすでに表示される。施設が紐付いた時点で候補に施設名が追加表示される)。落とし主は候補を見て施設に行き、施設の管理者が秘密情報と実物を対面で照合して本人確認を行う。実物が手渡された後、施設管理者がアプリ上で返却済みへとステータスを更新する。

会員登録・ログインを行うと、一般ユーザーと施設管理者で、トップページ以降に表示される画面・操作が異なる。

## 3. 対象ユーザーと役割

複数の施設(駅・警察署など)をまたいで利用できるアプリとして設計する。

### 3-1. 落とした人(一般ユーザー)
- 会員登録・ログインする(パスワードはハッシュ化して保存)
- 落とし物を登録する(種類・色・場所・日時・本人確認用の秘密情報・写真)。この登録一度きりで本人確認用の情報入力は完結する
- 自分が登録した落とし物の一覧・マッチング候補を確認する(施設情報が付いていれば合わせて確認する)。他人が登録した落とし物は閲覧できない
- 施設に行き、管理者との対面確認を経て実物を受け取る

### 3-2. 拾った人(一般ユーザー)
- 会員登録・ログインする(落とした人と同じアカウント種別。1人が両方の立場を兼ねられる)
- 拾得物を登録する(種類・色・場所・日時・写真)。この時点ではまだ施設は未設定でよい
- 実物を最寄りの施設(駅・警察署など)に届ける
- これ以降の対応(施設紐付け・本人確認・返却)には関与しない
- 拾得物一覧は、落とし主が候補を見つけられるようにするため、他の利用者が登録したものも含めて閲覧できる

### 3-3. 施設の管理者
- 会員登録時に「管理者コード」を入力し、所属施設を選択して登録する(管理者コードが正しくない場合は登録できない)
- 実物が届いたら、その拾得物データに自施設を紐付ける(保管開始。マッチング候補には施設紐付け前から表示されているが、この時点で候補に施設情報が追加表示される)
- 落とし主が来訪した際、登録された秘密情報(閲覧できるのは管理者のみ)と実物を対面で照合し本人確認する
- 実物を落とし主に手渡した後、アプリ上で「返却済み」にステータスを更新する
- 落とし物・拾得物の登録は行わない(管理者専用のトップページから、一覧画面のみへ遷移する)

## 4. 機能要件

### 4-1. MVP(必須機能)

| 機能 | 内容 |
|---|---|
| 会員登録・ログイン/ログアウト | メールアドレス・パスワード(bcryptでハッシュ化)でのアカウント登録、ログイン状態の管理(Cookie+署名によるセッション管理) |
| 役割の判定 | 会員登録時に管理者コードを入力した場合のみ施設管理者として登録される。所属施設の選択が必須 |
| 役割ベースの画面出し分け | 未ログイン/一般ユーザー/施設管理者で、トップページ・利用できる画面・操作を出し分ける |
| 落とし物登録機能 | 種類・色・紛失場所(大枠+詳細)・紛失日時・本人確認用の秘密情報・写真を登録できる。未来日時は登録できない |
| 拾得物登録機能 | 種類・色・拾得場所(大枠+詳細)・拾得日時・写真を登録できる。未来日時は登録できない |
| マッチング機能 | 種類・色・場所・日時の一致度をスコア化(0〜100点、DBに保存せず都度計算)し、候補を一覧表示する。拾得物は施設紐付け前でも候補として表示される |
| 本人確認機能 | 施設管理者が、登録された秘密情報(管理者にのみ表示)と実物を対面で照合し、一致すれば確定する |
| 施設管理機能 | 管理者が拾得物に自施設を紐付ける(紐付け後、候補に施設名が追加表示される)、返却済みへのステータス更新を行う |
| ステータス管理機能 | 落とし物・拾得物ごとに「未マッチング／返却済み」の状態を管理する。返却済みへの更新は施設管理者のみ実行できる(画面表示・Server Actionの両方で権限チェック) |
| データアクセス制御 | 落とし物一覧・詳細は登録者本人と管理者のみ閲覧可能。秘密情報は管理者のみ閲覧可能 |

### 4-2. 拡張機能(時間があれば追加)

| 機能 | 内容 |
|---|---|
| 管理者ダッシュボード | 自施設の未対応件数・返却済み件数などを集計・可視化する |
| メッセージ機能 | 落とした人と拾った人(または管理者)がアプリ上でやり取りできる |
| 通知機能 | マッチング候補が見つかった際にメール/画面通知を行う |
| 検索・絞り込み機能 | カテゴリ・場所・期間で一覧を絞り込む |
| 返却履歴機能 | いつ・どの管理者が返却対応をしたかを記録として残す |
| URLの直接アクセス制御(認可)の強化 | 現状、他人の落とし物のURLを直接知っている場合のアクセス制御までは対応していない(一覧・導線の出し分けまでが対応範囲) |

## 5. 非機能要件

| 項目 | 内容 |
|---|---|
| セキュリティ | パスワードはbcryptでハッシュ化して保存する。ログインセッションはHMAC署名付きCookie(httpOnly)で管理する。本人確認は施設管理者による対面照合とし、なりすましによる不正受け取りを防ぐ。返却済みへの更新・施設紐付けは管理者のみが行える(画面+Server Actionの二重チェック) |
| データアクセス制御 | 施設管理者は自施設に紐づく拾得物のみ管理操作できる。一般ユーザーは自分が登録した落とし物のみ閲覧できる |
| 対応デバイス | 一般ユーザー・管理者ともにスマートフォンからの利用を想定する |

## 6. 画面一覧(実装済み)

1. トップページ(`/`) — 未ログイン/一般ユーザー/管理者で表示内容を出し分け
2. 会員登録画面(`/register`) — 管理者コード・所属施設選択欄を含む
3. ログイン画面(`/login`)
4. 落とし物登録画面(`/lost-items/new`)
5. 落とし物一覧画面(`/lost-items`) — 一般ユーザーは自分の登録のみ、管理者は全件
6. 落とし物詳細画面(`/lost-items/[id]`) — マッチング候補、秘密情報(管理者のみ)、確定ボタン(管理者のみ)を表示
7. 拾得物登録画面(`/found-items/new`)
8. 拾得物登録完了画面(`/found-items/[id]/complete`)
9. 拾得物一覧画面(`/found-items`)
10. 拾得物詳細画面(`/found-items/[id]`) — 保管施設設定フォーム(管理者のみ)を表示

## 7. 業務フロー(概要)

```
[落とした人]                 [拾った人]                [施設管理者]
会員登録・ログイン            会員登録・ログイン          会員登録(管理者コード+所属施設)・ログイン
落とし物登録                 拾得物登録
(秘密情報を含む)              　↓
       ←──── システムが自動でマッチング候補を算出(施設未定でも表示) ────
                              実物を施設に届ける
                                                        施設を紐付け(候補に施設情報が追加表示)
候補を確認し施設へ向かう
       ↓
                                                        秘密情報(管理者のみ閲覧)と実物を対面で照合(本人確認)
       ↓                                                       ↓
実物を受け取る          ←─────────────────────────  実物を手渡す
                                                        アプリ上で「返却済み」に更新(matchesに確定記録)
```
